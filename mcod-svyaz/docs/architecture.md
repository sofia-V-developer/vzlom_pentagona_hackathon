# Архитектура

## Аппаратное предложение

```text
БС оператора ↔ направленная донорная антенна ↔ отдельный кабель
            ↔ донорный фильтр ↔ селективный двунаправленный репитер
            ↔ выходной фильтр ↔ делитель ↔ отдельные кабели
            ↔ внутренние панели А и Б ↔ телефоны персонала

Существующая GSM-антенна ↔ существующий GSM-модем → аварийные SMS
```

Выбран репитер с распределёнными панелями и профилем одного предполагаемого оператора. Профиль Band 7 использует UL 2500–2570 и DL 2620–2690 МГц. В демонстрации центры 2530 / 2650 МГц, ширина 20 МГц. Покрытие таким каналом на площадке требуется подтвердить. [ETSI TS 136 101, таблица 5.5-1](https://www.etsi.org/deliver/etsi_TS/136100_136199/136101/14.27.00_60/ts_136101v142700p.pdf)

Тракты физически разделены. Все новые фильтры расположены в новом оборудовании. Антенна и модем аварийных SMS остаются в исходном подключении и настройке. В приложении описание и модельная позиция существующей антенны доступны только для чтения. Редактируемые контрольные окна, пороги и потери связи относятся к модели воздействия.

Band 7 входит в указанный в кейсе диапазон существующей антенны 790–2700 МГц. Частотное разделение с GSM 900/1800 само по себе не подтверждает совместимость. Нужны проверки побочных излучений, PIM, IMD и перегрузки модема. Фактические каналы GSM, параметры и допустимые уровни модема открыты. Покрытие LTE требует отдельных проверок голосовой связи и поддержки VoLTE оператором, SIM и телефоном.

## Программная схема

```text
React + Recharts ── REST/polling ── FastAPI
                                      │
                                SimulationService ── SQLite
                                      │
                               SimulatorAdapter
                                      │
                 Сценарий → усиление и защита → карта и бюджет
```

Один серверный цикл продвигает модельное время запущенных МЦОД. При паузе состояние меняют только команды оператора. Обновление страницы читает backend. GET не записывает событий и не продвигает время. API возвращает метаданные `timestamp`, `simulation_time`, `config_revision`, `model_version`, `data_source` и `snapshot_id`. Идентификатор привязывает запрос бюджета и отчёта к отображённому снимку. Устаревший идентификатор возвращает HTTP 409.

МЦОД разделяются по идентификатору. У каждого свой профиль, ревизия, время, сценарий, фиксация защиты, журнал и история. SQLite сохраняет конфигурацию, модельное время, сценарий, фиксацию и события в одной транзакции. После рестарта время на паузе. В памяти на МЦОД хранятся последние 300 записей телеметрии и 24 полных снимка. Для добавления объекта в локальную демонстрацию положите валидный профиль в `configs/<id>.json` и перезапустите сервер. Интерфейс адаптера отделяет расчёт от HTTP. Текущая реализация использует только SimulatorAdapter.

## REST API

Префикс `/api/v1`. Для объектных операций ниже `S` означает `/sites/{site_id}`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health`, `/sites`, `/scenarios` | Проверка сервера, объекты, пресеты |
| GET / PUT | `S/config` | Базовая конфигурация. PUT принимает `{config_revision, config}`, конфликт ревизий даёт 409 |
| POST | `S/config/restore` | Восстановить демонстрационную конфигурацию |
| GET | `S/snapshot`, `S/history`, `S/events` | Текущие расчёты, история и журнал |
| POST | `S/scenario` | Выбрать `{scenario, seed}` и поставить t=0 на паузу |
| POST | `S/simulation/{action}` | `start`, `pause`, `step`, `reset`, `clear-trip` |
| GET | `S/imd-products?f1=1740&f2=2530` | Частоты продуктов и попадание в защищаемые окна |
| GET | `S/budget?x=6&y=1.5&snapshot_id=…` | Пошаговые бюджеты |
| GET | `S/export/config.json` | Конфигурация для переноса |
| GET | `S/export/report.{md,json,html}` | Отчёт. Необязательные параметры x, y и snapshot_id |
| GET | `/openapi.json` | OpenAPI |

API обслуживает мониторинг собственного стенда. Для реального размещения нужны аутентификация, роли, сетевое ограничение доступа, журналирование действий и отдельный подтверждённый адаптер. Демонстрационный сервис слушает loopback снаружи контейнера или при локальном запуске. Одну SQLite-базу обслуживает один серверный процесс.
